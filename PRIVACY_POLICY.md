# Halvern Privacy Policy

*Applies to Halvern 0.1.0. Last updated 23 August 2026.*

Most privacy policies are written to permit as much as possible. This one is
written to be checked. Every claim below names the file that makes it true, so
you can read the code instead of trusting the paragraph.

## The short version

Halvern records, transcribes and summarizes your meetings on your own machine.
There is no account, no upload step, and no server belonging to us. A default
build has nowhere to send anything and no credentials to send it with.

Three things can change that, and all three are choices you make:

- configuring an external LLM provider for summaries,
- configuring remote transcription,
- exporting to Obsidian or to a file you choose.

Nothing else leaves your computer.

## What stays local by default

- **Audio recordings** are written to `~/Movies/halvern-recordings` (macOS) and
  never sent anywhere.
- **Transcription** runs in-process using Parakeet or Whisper, downloaded once
  to your machine.
- **Summaries** are generated by a local model through the bundled
  `llama-helper` sidecar, unless you point Halvern at an external provider.
- **Meetings, transcripts and summaries** live in a SQLite database at
  `~/Library/Application Support/io.halvern.app/meeting_minutes.sqlite`.

## Telemetry

**A build you download from us sends no analytics, and cannot be made to.** This
is a property of how it is compiled, not a setting:

- The endpoint and key come from `option_env!("HALVERN_TELEMETRY_ENDPOINT")` and
  `option_env!("HALVERN_TELEMETRY_API_KEY")` (`analytics/commands.rs`), which are
  **compile-time** variables. Unset when the binary is built, they are `None`
  forever in that binary.
- The client is constructed only `if config.enabled && !config.api_key
  .is_empty()` (`analytics/analytics.rs`). With no key there is no client, and
  every send path returns early.
- Consent defaults to `false` in every branch of `AnalyticsProvider.tsx`.

If a build is ever produced with those credentials set, analytics remains **off
until you turn it on**, and would carry usage patterns and error reports only —
never meeting content, transcripts, audio, titles, or participant names.

We would rather say this plainly than describe a data pipeline that does not
exist: earlier versions of this document, inherited from upstream, described
retention periods and access controls for an analytics system this build has no
way to reach.

## When data does leave your machine

Each of these is off until you configure it.

**External LLM providers for summaries.** If you set an API key for OpenAI,
Anthropic, Groq, OpenRouter, or a custom OpenAI-compatible endpoint, the
transcript of the meeting being summarized is sent to that provider and is then
governed by their privacy policy, not this one. Ollama pointed at `localhost` is
local; Ollama pointed at another host is not.

**Remote transcription.** Halvern can send audio to an OpenAI-compatible
transcription endpoint instead of transcribing in-process
(`audio/transcription/remote_provider.rs`). This is the one setting that sends
raw audio rather than text. It exists so you can use your own server; pointing it
at a commercial API sends your meetings there.

**Model downloads.** On first run Halvern fetches speech and summarization models
from HuggingFace. Those requests reveal that some IP address is downloading a
model. They carry nothing about you or your meetings.

**Update checks.** Once per launch, if the setting is on, Halvern fetches one
static file from GitHub Releases — `latest.json` — to learn whether a newer
version exists. It is a plain GET, the same request a browser makes when
somebody clicks a download link. It has no body, carries no identifier, and
says nothing about your meetings, your usage, or your settings. GitHub sees
what any web server sees about any download: an IP address, a User-Agent, and
a time.

It runs **once per launch and never on a timer**, deliberately. A periodic
check would turn "is Halvern open right now" into a signal with a heartbeat,
and when you are in meetings is the thing this product exists to keep to
itself. Settings → General → *Check for updates on launch* turns it off, and
with it off nothing is requested until you press the button yourself.

What comes back is verified against a signing key compiled into the app, so an
update that was not built and signed by us is refused rather than installed.
The check is in one place — `updater.rs` — if you would rather read it than
take our word.

**Obsidian and file export.** Writes to the vault or folder you choose, on your
own disk.

**Calendar.** Halvern reads your local calendar to name recordings after the
meeting they belong to (`calendar/`). It is read-only, it stays on the machine,
and macOS asks your permission first.

## What we never collect

There is no "we" in the data path to collect anything. No component of Halvern
transmits meeting content, transcripts, audio, meeting titles, participant
names, file names, or generated summaries to us, under any configuration —
including one built with analytics credentials.

## Storage and security, stated accurately

Your data is stored as ordinary files with ordinary filesystem permissions.
**Halvern does not encrypt its database or its recordings.** If your disk is
encrypted — FileVault on macOS — then they are encrypted, because the disk is.
If it is not, they are readable by anything running as your user.

API keys you enter are stored in the same database, in plain text. Treat that
file the way you would treat the keys themselves.

We would rather be exact here than claim "encrypted at rest", which is true of
almost any file on an encrypted disk and tells you nothing.

## Your control

- **Access**: everything is in the two paths listed above. Open them.
- **Export**: Markdown or Obsidian, from the app.
- **Delete**: deleting a meeting in the app removes its rows and its recording.
  Deleting the two directories removes everything Halvern has.
- **Leave**: there is no account to close.

## Changes to this policy

Material changes will appear in this file in the repository and in the release
notes for the version that introduces them.

## Contact

Halvern does not yet have a public repository or an issue tracker, so there is
currently no address for privacy questions. This section will name one when the
project is published. It deliberately does not point at upstream's tracker,
contact form, or Discord — Halvern's handling of your data is not Zackriya
Solutions' responsibility, and sending you to them would misplace both the
question and the accountability.
